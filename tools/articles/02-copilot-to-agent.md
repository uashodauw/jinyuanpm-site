过去两年，大多数 AI 产品的形态是 Copilot：用户在自己的工作流里，随时唤起一个助手，由它给出建议、补全内容或回答问题。而近期越来越多产品开始探索 Agent：用户给出目标，系统自行规划、调用工具并完成多个步骤。

> Copilot 的核心是“增强”，Agent 的核心是“委托”。

## 交互范式的三个变化

**1. 从“逐步指令”到“目标描述”。** 在 Copilot 中，用户每一步都在主导；在 Agent 中，用户只描述想要的结果，过程交给系统。这意味着输入更短，但对“理解意图”的要求更高。

**2. 从“即时反馈”到“过程可见”。** 任务执行变长之后，用户需要知道系统正在做什么、做到哪里、遇到了什么问题。进度、计划、工具调用记录，成为新的界面元素。

**3. 从“用户确认每一步”到“用户在关键节点确认”。** 全部确认会让 Agent 失去意义，完全不确认又会让用户失去安全感。产品设计的重点，是识别哪些动作可以自动执行，哪些必须停下来。

## 一个简化的任务计划结构

在设计 Agent 的任务展示时，可以先把“计划”抽象成结构化数据，再决定如何呈现：

```json
{
  "goal": "整理本周用户反馈并生成周报",
  "steps": [
    { "id": 1, "action": "拉取反馈数据", "risk": "low",  "auto": true  },
    { "id": 2, "action": "聚类并提炼主题", "risk": "low",  "auto": true  },
    { "id": 3, "action": "发送周报给团队", "risk": "high", "auto": false }
  ]
}
```

其中 `risk` 与 `auto` 两个字段看似简单，却直接对应了“哪里需要用户确认”的产品决策。

## 设计 Agent 时的几个原则

- **可中断**：用户可以随时暂停、修改或接管。
- **可回溯**：每一步的输入、输出与依据都可查看。
- **可降级**：当 Agent 不确定时，退回到 Copilot 式的建议，而不是硬着头皮执行。
- **可授权**：权限随信任逐步放开，而不是一次性全部给予。

## 结语

从 Copilot 到 Agent，并不是简单的“能力升级”，而是人与系统之间关系的重新设计。谁来决定、谁来负责、出错如何补救，这些问题的答案，将定义下一代智能产品的体验。
